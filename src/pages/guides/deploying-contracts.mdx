## Deploying Contracts

This guide covers the full deployment workflow: local testing, testnet deployment, mainnet deployment, contract verification, deterministic addresses with CREATE2, and constructor arguments for `forge create`.

### Local deployment with Anvil

::::steps

#### Start a local node

```bash
$ anvil
```

Anvil provides 10 pre-funded accounts for testing. The first account's private key is `0xac0974bec39a17e36ba4a6b4d238ff944bacb478cbed5efcae784d7bf4f2ff80`.

#### Deploy your contract

```bash
$ forge script script/Deploy.s.sol --broadcast --rpc-url http://localhost:8545 --private-key 0xac0974bec39a17e36ba4a6b4d238ff944bacb478cbed5efcae784d7bf4f2ff80
```

::::

### Testnet deployment

::::steps

#### Create an encrypted keystore

Never use plaintext private keys. Import your key into an encrypted keystore:

```bash
$ cast wallet import deployer --interactive
```

#### Deploy to a testnet

```bash
$ forge script script/Deploy.s.sol --account deployer --broadcast --rpc-url https://sepolia.drpc.org
```

#### Verify the contract

```bash
$ forge verify-contract $CONTRACT_ADDRESS src/Counter.sol:Counter --chain sepolia
```

::::

### Mainnet deployment

For mainnet, use a hardware wallet:

```bash
$ forge script script/Deploy.s.sol --ledger --broadcast --rpc-url https://ethereum.reth.rs/rpc
```

Or with an encrypted keystore:

```bash
$ forge script script/Deploy.s.sol --account deployer --broadcast --rpc-url https://ethereum.reth.rs/rpc
```

### Constructor arguments with `forge create`

[`forge create`](/reference/forge/create) deploys one contract from the command line. You pass one shell argument per constructor parameter after `--constructor-args`. Forge reads the constructor from the compiled artifact and ABI-encodes the values.

Arrays use square brackets. Structs and tuples use parentheses, with fields in declaration order. Quote each value so the shell keeps the brackets, parentheses, and spaces together. Spaces after commas are optional.

```solidity
struct Point {
    uint256 x;
    uint256 y;
}

contract Markers {
    constructor(uint256[] memory ids, Point memory origin, Point[] memory points) {}
}
```

```bash
$ forge create src/Markers.sol:Markers \
    --rpc-url $RPC_URL \
    --private-key $PRIVATE_KEY \
    --broadcast \
    --constructor-args "[1, 2, 3]" "(0, 1)" "[(1, 2), (3, 4)]"
```

`[1, 2, 3]` is the `uint256[]`, `(0, 1)` is `origin`, and `[(1, 2), (3, 4)]` is the `Point[]`.

A struct that contains an array is one parenthesized argument:

```solidity
struct Bundle {
    uint256[] ids;
    uint256 nonce;
}

contract Bundled {
    constructor(Bundle memory bundle) {}
}
```

```bash
$ forge create src/Bundle.sol:Bundled \
    --rpc-url $RPC_URL \
    --private-key $PRIVATE_KEY \
    --broadcast \
    --constructor-args "([1, 2, 3], 7)"
```

Quote strings that sit inside an array or struct:

```solidity
struct TokenConfig {
    string name;
    uint256 supply;
}

contract NamedToken {
    constructor(TokenConfig memory config) {}
}
```

```bash
$ forge create src/NamedToken.sol:NamedToken \
    --rpc-url $RPC_URL \
    --private-key $PRIVATE_KEY \
    --broadcast \
    --constructor-args '("MyToken", 1000000)'
```

Addresses, booleans, and integers use the same literals as [`cast calldata`](/cast/abi-encoding). An empty array is `"[]"`. A struct with an `address` and a `bool` is `"(0xf39Fd6e51aad88F6F4ce6aB8827279cffFb92266, true)"`.

:::note
Put `--constructor-args` last. It consumes every following value, including a later flag such as `--broadcast`.
:::

`forge create` encodes these values for you. [`forge verify-contract`](/reference/forge/verify-contract) takes the constructor arguments already ABI-encoded, usually from `cast abi-encode`. See [Verification with constructor arguments](#verification-with-constructor-arguments).

### Contract verification

Forge can verify contracts on Etherscan and compatible explorers.

#### Automatic verification during deployment

```bash
$ forge script script/Deploy.s.sol --broadcast --verify --rpc-url https://ethereum.reth.rs/rpc # [!code hl]
```

#### Manual verification

```bash
$ forge verify-contract $CONTRACT_ADDRESS src/Token.sol:Token \
    --chain mainnet \
    --constructor-args $(cast abi-encode "constructor(string,string)" "MyToken" "MTK")
```

#### Verification with constructor arguments

If your contract has constructor arguments, encode them:

```bash
# For a constructor: constructor(address admin, uint256 supply)
$ forge verify-contract $CONTRACT_ADDRESS src/Token.sol:Token \
    --chain mainnet \
    --constructor-args $(cast abi-encode "constructor(address,uint256)" 0x1234...5678 1000000000000000000000000)
```

### Deterministic addresses with CREATE2

CREATE2 deploys contracts to predictable addresses based on the deployer, salt, and bytecode. See the [Deterministic Deployments guide](/guides/deterministic-deployments-using-create2) for comprehensive coverage including `foundry.toml` configuration requirements.

Quick example using [CreateX](https://github.com/pcaversaccio/createx):

```solidity [script/DeployCreate2.s.sol]
// SPDX-License-Identifier: MIT
pragma solidity ^0.8.13;

import {Script, console} from "forge-std/Script.sol";
import {Counter} from "../src/Counter.sol";

interface ICreateX {
    function deployCreate2(bytes32 salt, bytes memory initCode) external payable returns (address);
}

contract DeployCreate2 is Script {
    ICreateX constant CREATEX = ICreateX(0xba5Ed099633D3B313e4D5F7bdc1305d3c28ba5Ed);

    function run() public {
        bytes32 salt = keccak256("my-unique-salt-v1");
        bytes memory initCode = type(Counter).creationCode;

        vm.startBroadcast();
        address deployed = CREATEX.deployCreate2(salt, initCode);
        vm.stopBroadcast();

        console.log("Deployed at:", deployed);
    }
}
```

:::warning
For deterministic addresses, you must pin your `solc` version, `evm_version`, and disable metadata (`bytecode_hash = "none"`, `cbor_metadata = false`). See the [full configuration guide](/guides/deterministic-deployments-using-create2#configuring-for-determinism).
:::

### Deployment script patterns

#### Basic deployment script

```solidity [script/Deploy.s.sol]
// SPDX-License-Identifier: MIT
pragma solidity ^0.8.13;

import {Script, console} from "forge-std/Script.sol";
import {Counter} from "../src/Counter.sol";

contract DeployScript is Script {
    function run() public {
        vm.startBroadcast(); // [!code hl]
        
        Counter counter = new Counter();
        console.log("Counter deployed at:", address(counter));
        
        vm.stopBroadcast(); // [!code hl]
    }
}
```

#### Deployment with configuration

```solidity [script/Deploy.s.sol]
// SPDX-License-Identifier: MIT
pragma solidity ^0.8.13;

import {Script, console} from "forge-std/Script.sol";
import {Token} from "../src/Token.sol";

contract DeployScript is Script {
    function run() public {
        address admin = vm.envAddress("ADMIN_ADDRESS"); // [!code hl]
        uint256 initialSupply = vm.envOr("INITIAL_SUPPLY", uint256(1_000_000 ether)); // [!code hl]

        vm.startBroadcast();
        
        Token token = new Token(admin, initialSupply);
        console.log("Token deployed at:", address(token));
        console.log("Admin:", admin);
        console.log("Initial supply:", initialSupply);
        
        vm.stopBroadcast();
    }
}
```

### Verifying deployment

After deployment, verify the contract state:

```bash
# Check the deployed bytecode
$ cast code $CONTRACT_ADDRESS --rpc-url https://ethereum.reth.rs/rpc

# Call a view function
$ cast call $CONTRACT_ADDRESS "owner()" --rpc-url https://ethereum.reth.rs/rpc

# Check contract balance
$ cast balance $CONTRACT_ADDRESS --rpc-url https://ethereum.reth.rs/rpc
```
